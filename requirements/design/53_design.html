Design #53 — goal pages in the hub + goals move to issues

Requirement jwildfire/obot.roadmap#53 · companion requirement #71 (goals → issues) · from Ideas discussion #50 / #55 · Approved & implemented 2026-07-24

Plan reviewed and approved by @jwildfire 2026-07-24 (labels renamed to auto/draft; D1, D2, D4, D5 approved as proposed). Supersedes design #18 decision O2.

1. Summary

Standing goals move from files (obot.agent/goals/*.md) to hub goal issues, and the site gains one page per goal summarizing the goal and its member requirements, split by readiness. The design splits direction + membership (the goal issue — editable by @jwildfire with no PR ceremony) from the policy binding for autonomous selection (a thin registry that stays in obot.agent under the policy-file carve-out).

2. Representation: goal issues

  • One hub issue per goal, label goal, title prefix Goal:, kept open indefinitely — closing = retiring. GitHub-native custom issue types are an organization-plan feature, unavailable on this user-owned repo, so label + template is the formal mechanism (resolves the requirement's open question).
  • Requirements link to goals as native sub-issues (goal = parent), giving the goal issue GitHub's progress bar. Single-parent constraint: a requirement already parented by another requirement (phase children) inherits goal membership through its parent.
  • The goal issue body opens with a fenced YAML block — the machine-readable bits sub-issue links can't express: 
    ```yaml
slug: charts                    # obot-auto --goal <slug>
anchors:                        # priority order
  - jwildfire/obot.roadmap#35
backlog:                        # hub issues or owner/repo issue backlogs
  - jwildfire/safety.viz
```
  • An issue form template, .github/ISSUE_TEMPLATE/goal.yml, scaffolds new goals (YAML block + Intent + Boundaries).
D1 (approved): goals are goal-labeled issues with sub-issue membership links; no custom issue type.

3. Readiness labels

  • auto — ready for autonomous implementation: the #18 implementation-ready criteria (design signed off, repo work scoped, inside the grant matrix).
  • draft — needs @jwildfire input or steering before implementation.
  • Sessions apply and refresh the labels during triage and wrapup, audited against the #18 criteria; @jwildfire overrides at will. The labels are display — --auto selection still evaluates the criteria directly, so a mislabeled issue cannot grant itself eligibility.
D3 (approved, amended): label names are auto / draft (@jwildfire 2026-07-24), not the proposed ready-for-auto / needs-steering.

7. v2 amendment (2026-07-24, same day)

On reviewing the shipped goal issues, @jwildfire flagged the up-front YAML blocks and their staleness risk (a hand-maintained list duplicating the sub-issue links). Approved reshape:

  • Prose-only bodies. Goal issues carry no machine list. The only machine bit is a hidden <!-- goal-slug: … --> comment naming the site page.
  • Membership is generated, never maintained. Members = the sub-issue links, read live by --auto and the site collector; a newly linked sub-issue is automatically a member.
  • Priority is the selecting session's judgment at session start, guided by the goal's boundary prose and the #18 criteria — explicitly not sub-issue list order (@jwildfire: order-as-priority declined; priority labels are a future option if judgment underperforms). --increment still overrides.
  • The anchors/backlog distinction dissolves hub-side. Repo-level backlog feeds (e.g. jwildfire/safety.viz) move into goals/registry.json next to grant_profile — they are selection policy, and they can't be sub-issues anyway.
  • Lightweight tasks may live directly under goals without a requirement wrapper (@jwildfire, decided at v2 review): #66 → G1 charts, #70 → autonomy. Flagged, not linked: #44 (no clear goal), #27 (single-parent constraint — already under #24).
  • Freshness process: requirement #87 (weekly goal review, under goal #73) — a scheduled sweep proposing linkages, label refreshes, and orphan candidates as comments; @jwildfire applies. D4 (goal issues read-only for autonomous sessions) unchanged and now also protects membership/order.
