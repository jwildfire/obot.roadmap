## What happened

Jeremy's handover, delivered by voice and read at the start of the session: the fully autonomous multi-agent prototype is shut down. The readout was hard to argue with — the agent structure held, objectives and memory management were poor, most of the effort went into the orchestration itself, he had to redirect it constantly, and it never produced a release for him to review. The replacement is requirement sessions: five objectives broken into requirements and tasks, one requirement per session, running as long as it takes, with him driving rather than reviewing.

Decisions he made during the day, each recorded on the plan page in his words:

- The scaffolding is retired in one obot.agent pull request tagged as the next release; the previous tag and the git history are the archive.
- The desktop app is safety.viz-native — a self-contained local HTML and JavaScript app — and the open.gismo app arc parks for the talk.
- Sequencing went to a plan page before any session starts.
- Tracking becomes rigid: objective issues with requirement issues with linked task issues, every node with a definition of done, filed before a session starts; agents bound to issues and pull requests; nightly comments on the requirement, rolled up on the objective; a standup that reports complete / in progress / blocked and asks nothing that is not a blocked issue.
- Every session moves to Claude Code cloud sessions; nothing runs from the Mac through Remote Control.
- The merge lane becomes GitHub rulesets — checks and auto-merge on integration branches, his review on release branches — retiring the policy script.
- The connected GitHub account is the actor in the cloud; the obotclaw[bot] identity, whose key lives in the Mac's Keychain, retires with it.
- The existing charts and app objective issues are reused; three objectives are filed new.
- Parity means a static twin for every interactive chart, with no code export from the app.
- The standards move to the hub, in more detail than they had, and obot.agent thins to the core of the semi-autonomous approach, written against Claude Code's own best practices.
- Late in the day, one design tweak: the five are objectives, not goals, and a session runs one requirement, not one objective — Objectives → Requirements → Tasks, with the requirement's definition of done as the condition the `/goal` evaluator judges.
