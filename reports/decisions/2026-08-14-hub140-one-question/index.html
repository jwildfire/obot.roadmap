Why it stalled — a diagnosis, not a complaint

  • It is two things stapled together. A delivered requirement (the profile model: shipped, verified 80/80, release-noted) and an undelivered enforcement design (Gates A/B, truthful --check). The issue reads as if the whole thing is pending, so re-reading it costs far more than the ask warrants.
  • Eight decisions is a format failure. Seven of D1–D8 are schema shapes, exit codes, matching semantics, and test placement — each already argued to a recommendation in the design itself. The 2026-08-01 comment asked for a review of all eight as a block; thirteen days of silence is the answer to that format, not to the substance. (D1–D8 predate the decision-artifact lane by two weeks; this page is the ask restated in the format that worked four times tonight.)
  • The scope kept growing while it waited. Gate B was found while designing Gate A (now oa#75); the oa#83 forensics landed on oa#65 tonight; obot-policy explain’s silence and policy.json’s self-contradiction were added tonight too. Every addition made “read it all again” more expensive without changing what is actually being asked of you.

4 · The decisions

W1 · was D4 · the one policy call

What does the carve-out require?

Today policy.json gives two answers. carveOut._note: PRs touching guardrail paths “merge only with @jwildfire’s approval, even on a standard-lane branch in an ‘auto’ repo.” invariants.never: never merge one unattended. On oa#83 those readings disagreed about a real merge, the body claimed one lane, the tool used the other, and nothing noticed for a day. The gate being built (oa#65) must know which rule it enforces.

a · Attested-always recommended

Meaning
Any PR touching a carve-out path merges only with --jeremy-approved '<where/when>' — attended or not, any lane, any profile. The 🔒 audit comment becomes the permanent lane marker.
Costs
One flag plus an audit comment on the handful of guardrail PRs a month. Unattended sessions can never land one — which was always the intent.
Forecloses
Nothing. The invariant text is rewritten to match the note, ending the contradiction.

b · Unattended-bar only

Meaning
Attended standard-lane merges of guardrail PRs stay flag-free; only unattended ones are barred.
Costs
Barely implementable: obot-merge cannot observe whether the invoking session is attended, so the gate would rest on the caller’s honesty — which is the status quo that failed twice. And an attended guardrail merge leaves no marker; tonight’s oa#83 forensics only worked because the absence of a 🔒 comment was conclusive.
Forecloses
A trustworthy audit trail for the guardrail files.
Recommendation

W1a — attested-always. If the carve-out only restates what the standing contract already requires, the list is decorative. Two good-faith violations in sixteen days is what “decorative” looks like in practice; a flag the tool refuses to proceed without is what “real” looks like.

5 · The cost of another thirteen days

What stays true while this goes unanswered — each verified in tonight’s code, not inferred:

  • The carve-out gate does not exist. obot-merge fetches baseRefName,isDraft,state,mergeable,headRefOid,url,title — no file list — so a PR rewriting scripts/policy.json on obot.agent main merges on the standard lane with no flag and no resistance, including for an unattended session. The only thing preventing it is prose in a skill file, and prose has now failed twice (oa#61 on 07-29, oa#83 on 08-14 — the second while claiming compliance). Both were caught by after-the-fact forensics, not by anything at merge time.
  • Every attested merge risks a false audit trail. The 🔒 “explicitly approved by @jwildfire” comment posts before the merge attempt, so a conflicting PR gets an attestation for a merge that never happened — on the lane whose entire point is the audit trail.
  • You get told merges will work when they won’t. --check prints “CHECK PASSED — policy permits merging” for PRs GitHub will refuse, and the mergeable value it shows is usually UNKNOWN (first-query artifact). In practice: you approve, the agent reports a passing check, and the merge dies at the last step — the exact sequence discussion #141 was filed about on 07-29.

The honest weighting. Continued silence is cheap in immediate damage — there is no adversary, both violations were procedural, no bad change went out. It is expensive in exactly the currency the program is spending this month: v0.4.0’s notes present policy.json as the guardrail while its enforcement hole is documented in two open issues, the RC lane’s audit trail is unreliable on the one lane that exists for auditability, and the expected result of doing nothing is a third silent violation found by a future sweep. The asymmetry is stark: the fix is blocked on roughly three checkboxes, and the implementation is one PR that was fully specified two weeks ago.
