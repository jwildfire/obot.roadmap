WHAT IS BEING DECIDED

"Scheduled sessions" means something specific here: the autonomy policy file defines three levels, and the workspace currently runs at the middle one — an autonomous dev session may merge routine work on its own, but a human still types the launch command. The next level up is defined, in the policy's own words, as "scheduled — nightly trigger without a human launch (not yet enabled)." Turning that on is this decision. The launcher script already exists and runs a fail-fast pre-flight (guardrail file validates, kill-switch file absent, goal registered and active, bot credentials mint, no second autonomous session already running); what does not yet exist is the thing that invokes it on a schedule, and the thing that notices when a run nobody launched fails.

HOW YOU FIND OUT AT 3AM — DETECTION AND ALERTING

The demo study taught the design principle: never alert on failure; alert on missing success. A failure event needs a subscriber, and subscribers rot. An expected-success check has no such dependency — if the thing that should have happened by 07:00 has not happened, that is the alarm, even when every failure signal was swallowed.

The proposed chain, each layer watching the one below it:

  • The run itself ends every path — success, park, abort — with a wrapup digest and a final scratchpad line. (The page also proposed a rule parking any run that is refused a write; that is now a nice-to-have, since the refusal it was written for did not exist.)
  • The watchdog (Fix 2) extends the already-proven five-minute Navigator sweep with three checks: overnight session health read from job state on disk (a session "blocked" or silent past thirty minutes is flagged, catching both the unrevivable-death and the stall-looking-healthy cases); scheduled-workflow conclusions across all seven repos (the demo-study class of failure — this check would have flagged that pipeline eleven days ago, and will flag it on day one until triaged); and the dead-man check — by 07:00, last night's run must have produced its digest, and a missing digest is a red flag even if nothing reported failure, which also covers "the trigger itself never fired" and "pre-flight failed and exited silently."
  • Who watches the watchdog: its state file carries the Navigator's self-describing staleness rule — any reader finding a timestamp older than three ticks must treat the observer as dead and say so. The morning session-init and the concierge both read that file, and the ops dashboard renders it; your first interaction of the day is therefore a human-touched check of the monitor itself. A dead watchdog cannot masquerade as a quiet one.
  • Your terminal: the morning digest — one message: what ran, what landed, what parked and why, watchdog status. Whether anything should reach your phone during the night is question S3; the recommendation is no, because every overnight outcome the fixes leave possible is a safe stop that can wait for morning.

SCOPE PER RUN, AND THE STOP CONDITIONS

What one scheduled run is allowed to attempt — all but the last two lines already enforced by the launcher and the guardrail file:

  • One increment, one run, from the registered active goal, four-hour wall-clock budget; caps park the work with a digest at a phase boundary.
  • One autonomous session at a time — the launcher refuses if another is running.
  • Writes only in promoted repos, only on working branches. Published surfaces, tags, releases, deletions: never (Fix 3 turns the last of these from prose into a gate).
  • Kill switch: one halt file parks everything at the next phase boundary; its absence is checked again at every launch.
  • A call it cannot make — an unsigned design, a clinical judgment, a rule conflict — becomes a decision artifact, and the run moves on or parks; it never guesses.
  • Changing a guardrail file — the policy that defines these lanes, the merge tool, the merge-blocking hook: never on a run's own authority. Enforced by the tool as of last night; a run that thinks the rules need changing must stop and write you the question.
  • A denied write is retried once, then parks the run with a digest — proposed as part of the withdrawn first fix, now a nice-to-have rather than a precondition.
