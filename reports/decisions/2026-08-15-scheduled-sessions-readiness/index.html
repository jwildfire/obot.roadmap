WHAT IS BEING DECIDED

"Scheduled sessions" means something specific here: the autonomy policy file defines three levels, and the workspace currently runs at the middle one — an autonomous dev session may merge routine work on its own, but a human still types the launch command. The next level up is defined, in the policy's own words, as "scheduled — nightly trigger without a human launch (not yet enabled)." Turning that on is this decision. The launcher script already exists and runs a fail-fast pre-flight (guardrail file validates, kill-switch file absent, goal registered and active, bot credentials mint, no second autonomous session already running); what does not yet exist is the thing that invokes it on a schedule, and the thing that notices when a run nobody launched fails.

Recommendation

Go — enable late next week, after the four blocking fixes below land and one supervised end-to-end rehearsal of the full path (scheduled trigger → pre-flight → session → morning digest → watchdog report) completes cleanly. The guardrails that decide what a run may write held up well under this week's load, and were re-tested for this page. What is not ready is everything around a run that fails: today a 3am failure would be discovered whenever you happened to ask.

WHAT GENUINELY IMPROVED THIS WEEK

Credit where it is due, because several of these are load-bearing for the recommendation:

  • The agent tooling repo has CI for the first time — and its very first run caught a real Mac-only test bug. Before this week, the repo whose scripts gate every merge had nothing to catch its own breakage.
  • The Navigator sweep is live and proven. A five-minute scheduled job (not a session) watches every release-candidate PR, writes a state file with per-line "verified against GitHub at HH:MM" stamps, and declares its own staleness rule — if its timestamp is older than three ticks, readers must treat it as dead. On its first morning it caught a review you had left, unprompted, with no session involved. This is the pattern the watchdog below extends.
  • Enforcement gates now exist where prose used to be: the merge tool refuses a PR whose issues carry no milestone; a CI check fails the chart-library companion package when its widgets fall behind the JavaScript renderers; the hub deploy fails on an artifact without a plain-English description, on a duplicate decision ID, and on a decided artifact with no machine-readable decision record.
  • The concierge session keeps its state on disk and rehydrates from it, so a restart no longer forgets the queue.
  • The blockers list exists — the work only your hands can do is now one canonical, verified-dated file instead of scattered chat asks.

HOW YOU FIND OUT AT 3AM — DETECTION AND ALERTING

The demo study taught the design principle: never alert on failure; alert on missing success. A failure event needs a subscriber, and subscribers rot. An expected-success check has no such dependency — if the thing that should have happened by 07:00 has not happened, that is the alarm, even when every failure signal was swallowed.

The proposed chain, each layer watching the one below it:

  • The run itself ends every path — success, park, abort — with a wrapup digest and a final scratchpad line. A denied write parks the run rather than looping (Fix 1's rule).
  • The watchdog (Fix 2) extends the already-proven five-minute Navigator sweep with three checks: overnight session health read from job state on disk (a session "blocked" or silent past thirty minutes is flagged, catching both the unrevivable-death and the stall-looking-healthy cases); scheduled-workflow conclusions across all seven repos (the demo-study class of failure — this check would have flagged that pipeline eleven days ago, and will flag it on day one until triaged); and the dead-man check — by 07:00, last night's run must have produced its digest, and a missing digest is a red flag even if nothing reported failure, which also covers "the trigger itself never fired" and "pre-flight failed and exited silently."
  • Who watches the watchdog: its state file carries the Navigator's self-describing staleness rule — any reader finding a timestamp older than three ticks must treat the observer as dead and say so. The morning session-init and the concierge both read that file, and the ops dashboard renders it; your first interaction of the day is therefore a human-touched check of the monitor itself. A dead watchdog cannot masquerade as a quiet one.
  • Your terminal: the morning digest — one message: what ran, what landed, what parked and why, watchdog status. Whether anything should reach your phone during the night is question S3; the recommendation is no, because every overnight outcome the fixes leave possible is a safe stop that can wait for morning.
BLOCKING — EACH JUSTIFIED BY SOMETHING THAT HAPPENED
Fix 1 · blocking

Unstick the sanctioned lanes, and adopt deny-then-park

Why: the guardrail-hardening PR is finished and denied in every sanctioned landing form, and the agent that hit the wall was denied recording the fact. An unattended lane cannot open with its own merge tool intermittently refused and its failure-recording paths blocked.

What: a short batch of permission lines for you — kept, by design, on the local blockers list rather than on this public page; the ones needed here are the merge-lane line, the two capture-script lines, and whatever the landing-command denial turns out to need. Plus one standing rule written into the autonomous-session skill: an unattended run that is denied a write retries once, then parks with a digest — never loops, never proceeds unrecorded. Landing the blocked PR then also delivers the rule-collision fix and its regression test, and needs your one sign-off line (its own gate, correctly, holds it for you).

Cost: ~10 minutes of your hands + about an hour of agent work for the park rule.

Fix 2 · blocking

The overnight watchdog with a morning dead-man check

Why: one session died unrevivably and was caught only by a hand-armed monitor; a watcher was harness-killed silently; and an existing scheduled job has been red for twelve days with zero notifications. Three independent demonstrations that this lane currently has no detection that survives the night.

What: extend the Navigator sweep (already scheduled, already session-independent, already proven) with the three checks described above: overnight-session health, scheduled-workflow conclusions in all seven repos, and the 07:00 missing-digest alarm. Surface in the state file, the ops dashboard, and the morning digest.

Cost: about half an agent-day. No hands of yours.

Fix 3 · blocking

Hard stops on the destructive routes

Why: "never delete, never force-push" is enforced today by sentences, and this morning a sentence lost — an agent force-pushed against its own written constraint (carefully, and harmlessly, but that is luck plus judgment, not a guarantee). The API route the close-deny leak exposed is the same route a delete would take.

What: extend the existing merge-guard hook — the one already blocking raw merges on every route — to deny deletion endpoints, force-pushes, and release-publish/tag operations from agent shells, on CLI and API alike. This is a guardrail change, so it lands through the carve-out with your sign-off, which is exactly the process working as designed.

Cost: one to two agent-hours + your sign-off line.

Fix 4 · blocking

Build the trigger, then rehearse once — supervised

Why: nothing currently invokes the launcher on a schedule — the level above today's is explicitly marked "not yet enabled," and the one prior attempt at a scheduled agent job (the nightly diary routine, in the cloud) has been paused since early July because its environment could not push. The scheduled path has never once run end-to-end.

What: a scheduled system job on this machine (the same mechanism the Navigator uses, which survives session death and has run all day) invoking the existing launcher with its logging captured; then one full rehearsal on an evening you are around: trigger fires → pre-flight → session runs a real increment → digest lands → watchdog reports it. Also a kill-switch drill: with the halt file present, the trigger must fire and refuse, visibly.

Cost: about an hour of agent work + one supervised evening run.

NICE-TO-HAVE — REAL, BUT NOT GATING
  • Symmetric guard on the issue-close API route. Not gating because policy explicitly permits evidence-cited closes and both observed uses were approved; Fix 3 covers the destructive subset that matters.
  • Morning cross-check of approval-lane merges against your actual recorded approvals — closes the fabricated-attestation trust gap honestly rather than pretending it is enforced.
  • Repair or explicitly disable the demo study's red pipeline before the watchdog's first morning, so day one is signal rather than a twelve-day-old known failure. It is tracked as its own hub issue; it should not gate a lane it is not part of.
  • Overnight phone push for a wrong-write class alert (S3) — recommended against for week one, since the fixes aim to make that class impossible and every remaining overnight outcome is a safe stop.
  • A duplicate permission entry cleanup: one command appears on both the allow and the deny list in the user-level settings (deny wins, so there is no hole — but it is drift worth clearing while editing that file for Fix 1).
SCOPE PER RUN, AND THE STOP CONDITIONS

What one scheduled run is allowed to attempt — all but the last two lines already enforced by the launcher and the guardrail file:

  • One increment, one run, from the registered active goal, four-hour wall-clock budget; caps park the work with a digest at a phase boundary.
  • One autonomous session at a time — the launcher refuses if another is running.
  • Writes only in promoted repos, only on working branches. Published surfaces, tags, releases, deletions: never (Fix 3 turns the last of these from prose into a gate).
  • Kill switch: one halt file parks everything at the next phase boundary; its absence is checked again at every launch.
  • A call it cannot make — an unsigned design, a clinical judgment, a rule conflict — becomes a decision artifact, and the run moves on or parks; it never guesses.
  • A denied write is retried once, then parks the run with a digest (Fix 1's rule).
PRE-FLIGHT CHECKLIST — RUN BEFORE ENABLING, EVERY ITEM VERIFIABLE
  • The launcher's own pre-flight passes (it has a check-only mode that validates the guardrail file, the kill switch, the goal registry, credential minting, and single-session).
  • The guardrail-hardening PR shows merged, and a dry-run of the merge tool against any open release candidate still answers "your approval required."
  • The permission batch is in place: the merge-lane, capture-script, and landing-command lines resolve without classifier involvement (verifiable by running each once).
  • The watchdog is installed and fresh: the scheduled job is listed, its state file's timestamp is within three ticks, and its workflow-conclusion check reports the known red pipeline (proof it can see failures).
  • The destructive-route guard denies a harmless probe of a deletion endpoint (test the gate, not the luck).
  • Kill-switch drill passes: halt file present → trigger fires → launch refused, visibly logged; file removed → next fire launches.
  • The supervised rehearsal completed end-to-end with a digest you actually received by morning.
