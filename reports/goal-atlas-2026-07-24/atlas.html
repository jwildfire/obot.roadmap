Goal Atlas · Part 1

Four views of one graph

Goals, requirements and tasks are a single hierarchy held together by GitHub sub-issue links. Each view below reads that hierarchy a different way — coverage, proportion, detail, and everything the hierarchy misses.

Every mark is clickable and opens the issue on GitHub. Hover for repo, goal, stage and state.

View 2 · Strata

An icicle read left to right: goal, then its requirements and direct tasks, then their tasks. Every band's height is the number of open issues underneath it, so the picture is proportional — a goal with one member is one row tall, and the unclaimed block is as tall as the work it holds. Closed issues are excluded here; the point is what is live.

Reading it: Charts has real depth — ten members, one of which (hub#88, hepExplorer follow-ups) carries eight tasks of its own. App and Keynote are one band each. Unclaimed has the same internal structure as a goal — requirements with tasks under them — it simply has no goal on top.

View 4 · The unclaimed, sorted into homes

Forty-five open issues roll up to no goal. They are not a pile — they fall into five groups with clean edges. Two of the groups belong under goals that already exist; three describe workstreams the current goals were never written to hold. Part 2 turns those three into draft goals.

Open issues by goal and board stage. "Off board" means the issue is not an item on the obot Roadmap project, so it renders in no lane on the public roadmap page.

How the views were built

  • Membership is resolved at read time by walking subIssues from each goal issue to any depth, exactly as the hub#53 policy defines it. An issue whose parent chain never reaches a goal is unclaimed, even if it has a parent.
  • Kind is inferred: the goal label makes a goal; a requirement label or a Requirement: title prefix makes a requirement; everything else is a task.
  • Stage comes from the Status field on the obot Roadmap project (number 1), not from labels.
  • Color encodes goal identity only, in a fixed order so that every on-screen pair is one of the validated adjacent pairs. Every colored mark also carries a letter glyph or a written label, so identity is never color alone.
  • State is a shape, not a hue: filled dot for open, hollow for closed, ring for not-on-the-board.
