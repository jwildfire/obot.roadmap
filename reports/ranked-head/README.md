# The ranked head — the next ten and the bench

A living surface, not a dated snapshot: `index.html` is generated, and regenerating it
re-reads both records rather than editing anything by hand.

Requirement: [obot.roadmap#297](https://github.com/jwildfire/obot.roadmap/issues/297).
The mechanism it reads is [#278](https://github.com/jwildfire/obot.roadmap/issues/278).

## How it is generated

```bash
# from a jwildfire/obot.agent checkout
node tools/rankviz/build.mjs --out ../obot.roadmap/reports/ranked-head/index.html
```

The generator lives in [`jwildfire/obot.agent`](https://github.com/jwildfire/obot.agent)
at `tools/rankviz/`, beside the rank store it reads. It writes one self-contained file
and nothing else.

## Sources

| what | from | when it was read |
|---|---|---|
| The order, and the one-line reason per item | `rank/top10.json` in obot.agent — the single declared store | the commit that last touched it, stated on the page |
| Membership — which ten, and who is on the bench | the `top10` and `on-deck` labels on jwildfire/obot.roadmap | build time, stated on the page |
| Title, state, milestone, blocked, sub-issue progress | GitHub REST, derived at build time | build time, stated on the page |
| How the order has moved | every commit against `rank/top10.json`, with the store's bytes asked for at each commit | the commits themselves |
| How membership has moved | GitHub `labeled` / `unlabeled` issue events for the two labels | build time |

Two clocks, never merged: how old the order is comes from the commit that last touched
the file, never the file's timestamp; how old the state beside it is comes from when
GitHub last answered.

## Assumptions, and what the page refuses to do

- **There is no `high priority` label.** @jwildfire asked for one on 2026-08-19 and then
  said *"Let's just make a 'top10' label for those requirements"*. The page renders that
  one population in its two tiers and invents no third.
- **The ranked record is one day deep**, and the page says so in the masthead rather than
  leaving a reader to infer it. The rails are the only thing drawn against time and they
  stop where the record stops; the player's scrubber steps by commit and says it is not a
  time axis.
- **Nothing is interpolated.** A commit whose store will not parse produces a frame that
  prints its own reason and draws nothing, and the transitions across it are left blank.
  The reversal search reports how many frames it could not read.
- **The bench is unranked**, on screen as well as in the data. Ordering it would invent a
  decision nobody has made.
- **Findings are shown, not resolved.** A `top10` label on a closed issue is a slot open;
  the page says which rank and stops. Choosing the replacement is 🎩🤖 obot-prime's.

## Why the stylesheet is inlined

The page inlines `assets/obot.css` from obot.agent rather than linking
`site/assets/obot.css` here. Reports are self-contained single files by contract, which is
the case the shared sheet's own header names for inlining, and it keeps the artifact
readable from disk without the site around it. The bytes still come from the one canonical
sheet — the generator imports it rather than keeping a copy.

## Disclaimer

Generated by an LLM agent (Claude Code, Opus 5). Every figure on the page is read from
`rank/top10.json`, its git history, or the GitHub API at build time; none is written by
hand, and each is labelled with where it came from and when it was read.
