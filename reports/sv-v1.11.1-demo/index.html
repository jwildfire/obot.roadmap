safety.viz release 1.11.1 13 October 2026

What v1.11.1 changes, annotated

Release 1.11.1 is a patch to the demo app. Wherever R can be started, a note at the top of the card now says why R is wanted and what starting it costs, with Start R inside the sentence. Every note in the app is now blue for information or amber for something that cannot run, and the line on first open is removed. No chart and no metric is added, and nothing the app computes changes.

111 of 111 things this page says, held to the live site by a script captured 13 October 2026 from the released site public pilot study: 254 participants with 110 synthetic participants in its labs file

01 · the note

A note at the top of the card says why R is wanted

A reader on a chart that can start R is now told so where they are looking, and can start R from that sentence. In release 1.11.0 the chart said “Statistics need R. Start R, at the top right.” and the reader had to find the control.

Requirement: a standard note where R can be started (obot.roadmap #420) Task: put the R note on the biomarker charts and the RBQM tab (safety.viz #322) Pull request: the note where R can be started (safety.viz #325) As drawn in the design’s first mockup

Blue, where R adds p-values

Amber, where nothing is drawn without R

  • Blue is on the charts that draw without R and gain p-values from it: Association scatter, Cross-tabulation and Group comparison.
  • Amber is on the charts that draw no result without R: Correlation matrix and Biomarker screen. The RBQM tab has the same amber note (section 04).
  • All five charts give the same cost: “about 13 MB, downloaded once. The study’s data stays in this browser.”
  • The note’s button and the control are one press. With Start R pressed on the control, the note on the Correlation matrix turned to “R is starting. The chart is drawn when it is ready.” and lost its button, so R cannot be started a second time.
  • R still starts only when asked: until one of the two is pressed the page asks nothing of R’s addresses (0 requests).
  • The sentence inside the chart is one the app hands to the chart, so the chart library did not change: the chart’s footer still reads “Drawn on 2026-10-14 by bio.viz 0.3.0. Statistics: unavailable, as the line under the chart says.”

02 · the note follows R

The note follows R: starting, did not start, ready

While R starts the note says so, with a turning ring and no button. When R did not start it says what the chart is left without, with Try again inside the sentence. Once R is ready there is no note.

R stopped answering
“R stopped answering, so no metric was run. Try again The reason is behind Why, at the top right.” A reader meets it when R gives no answer for longer than the tab waits while R starts, loads gsm’s packages or runs; the tab then closes that R.

03 · closing the blue note

A reader who does not want p-values can put the blue note away. It is closed for the visit on all three charts that have it, and the control at the top right still starts R.

07 · what did not change

What did not change

Release 1.11.1 changes where the app says R can be started, and how its notes look. It does not change what the app works out.

  • No chart is added and no metric is added.
  • The app is still labelled “Exploratory”, and its status panel still counts: “13 charts are Exploratory. 5 charts and the RBQM tab are Experimental.”
  • The control at the right end of the chart names reads the same on both sites: “Statistics need R · 13 MB, once · Start R” on the Biomarkers tab and “Site metrics need R · 55 MB, once · Start R” on the RBQM tab.
  • R still starts only when asked. Before a press the page had asked nothing of R’s addresses, on the Biomarkers tab (0 requests) and on the RBQM tab (0).
  • R’s answers read the same on both sites. On the Association scatter: “Pearson's product-moment correlation: p = 0.129 (n = 230). Exploratory, unadjusted.” On the Cross-tabulation: “Pearson's Chi-squared test: p < 0.001 (n = 254). Exploratory, unadjusted.”
  • A real run of the RBQM tab on the pilot study ends in the same line on both sites, but for its seconds, and the first row of the site overview is the same: “R ran 3 of 8 metrics on the Pilot study in 2.9 seconds. The other 5 need data it does not have: change the data on the Data tab.”
  • No file of R’s changed, and no chart’s code changed: the release notes say so, and the footer of a biomarker chart still names the chart library as it was, “bio.viz 0.3.0” (the release notes).
  • What holds the note in place is a set of browser tests named by requirement rows: APP-NOTE-003 and APP-PAGE-044 for the standard note and the first screen, APP-R-060 to APP-R-063 for the note on the biomarker charts, and APP-RBQM-082 for the RBQM tab (safety.viz #324; safety.viz #325).
08 · before you approve

For your ruling

Six things, none of which held the release

  1. The sentences in the notes are drafts

    They ship as drafted and are yours to correct. Every one is printed under every sentence the note says, and the two this page cannot picture under sentences this page does not picture.

  2. No seconds in the note while R starts

    • The design page drew seconds in the note: “13 MB · 4 s” (the design’s second mockup).
    • The build leaves the seconds to the control. The note reads “13 MB” and the control “Starting R · 13 MB · 3 s” (the picture).
    • The reason is a standing rule that keeps one count on the page (requirement row APP-RBQM-019).
    • Say if you want the seconds in the note as well.

  3. Three cases moved from red to amber

    • A chart with no file loaded, which was a red card: “No file loaded for: Adverse events.” (the picture).
    • A chart with a column not mapped, which was a red card: “Not mapped yet: Result.” (the picture).
    • The RBQM tab’s line when R did not start, stopped answering or stopped, which was red text: “R did not start, so no metric was run. Try again The reason is behind Why, at the top right.” (the picture).
    • Red is kept for a chart that was ready and failed, and for the control’s “R did not start”.
    • One more move, not from red: a metric the loaded study cannot support said why in a box with a purple edge, and now says it in an amber note (the picture).

  4. The RBQM tab has one note while R is ready

    • The design said that once R is ready there is no note.
    • The build has one, in one state: R is up and nothing has yet run on what is loaded. A blue note reads “R is ready. Run the metrics on what is loaded now.” (the picture).
    • In release 1.11.0 this state was a line of text: “R is ready. Run the metrics from the R chip, at the top right.”
    • Say if you want it otherwise.

  5. The hub’s line on one control that starts R

    • The hub’s developer guidelines say: “One way to do a thing across an app: one control that starts R, in one place” (the guidelines, designing and checking what people look at).
    • The approved design adds a second place to press, the note. Its button calls the control’s own press.
    • safety.viz’s contributing guide was reworded to say so. The hub’s line was not (the contributing guide’s demo app conventions).
    • Proposed wording for the hub’s line, yours to accept: “one control that starts R, in one place; a note may repeat its press inside a sentence, and it is the same press”.

  6. The requirement is not yet linked under the demo-ready objective

    The requirement for the standard note names that objective, but is not yet one of its linked requirements. That link is yours (the objective: a demo app ready to show, obot.roadmap #401; the requirement, obot.roadmap #420).

Not in this release

  • A button inside the chart’s own line. That line is drawn by the chart library, so it would need a release of the library; the app changes only the words it hands over (the design’s list of what is left out).
  • The chart library naming for itself which charts cannot be drawn without R. For now the app names the two (the requirement’s design section).
