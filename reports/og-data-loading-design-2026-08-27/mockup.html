Two domains were never delivered. That is normal — not every CRO exports an audit trail or a query log. The question is not whether the run can proceed but whether you know what it costs, so the choice is made here and recorded rather than discovered later as an empty chart.

The whole output of this screen is source_col lines in the project's own mapping workflows, plus file paths in data-config.yaml. No new transformation layer, no second spec format, nothing for gsm.mapping to learn. The engine already reads exactly this.

The delivery in this mockup is hand-authored to be realistically uneven, and it was written before the alias table it is matched against, so the matcher gets no help from having seen it. It scores 45% against ADaM, which is roughly what a real CRO extract looks like.

What each step is for

Step 1 — profile before you judge

  • Today's og_validate() never prints what the user actually has. It reports what is missing against the target names and stops. The user is left to open the CSV themselves to find out what the columns are called.
  • Naming the standard is the safetyGraphics move, and it is what turns a wall of red into a job with a known size: "Partial ADaM, 19 of 42 standard names present" tells the reader the delivery is broadly conventional and the work is bounded.
  • The formats line is the honest one. open.gismo reads CSV and only CSV, in every one of its loaders. Real deliveries arrive as SAS transports.

Step 2 — the screen that does not exist

  • Domains are ordered by what they control, not alphabetically. Raw_SUBJ is first because it feeds 22 of the 25 metrics; Raw_STUDY is last because it feeds none.
  • Each row is one source_col decision. Green rows are already settled, amber rows are a proposal to confirm, red rows are the real work.
  • Resolving one row can change everything on the page. Raw_SUBJ.invid has no candidate in this delivery, because the CRO calls it CENTRE_CODE and no alias list knows that. It is one dropdown, and 12 metrics hang on it.
  • Conflicts are surfaced rather than resolved silently. Three columns in Raw_STUDY all match PROTOCOL; a machine should not pick.

Step 3 — absence as a decision

  • Today an absent domain either aborts the run hard (Ingest()) or is logged and skipped (fs_LoadData()), depending on which path reaches it first. Neither is a choice the user made.
  • Naming the cost in metrics converts "your data is incomplete" into "this run gives you this many of the 25 metrics, and here are the ones you are giving up".

Step 4 — emit and re-check

  • The artifact is a diff against files the user already owns, shown before it is written.
  • One target column can be declared in more than one mapping file — Raw_SUBJ is declared in both SUBJ.yaml and STUDY.yaml — so an edit has to land in every file that declares it. That is a consistency trap a person editing YAML by hand will eventually fall into, and the reason the surface should write the files rather than tell the user which ones to open.
  • Ending on a green re-validation is the point. The current product can tell you that you are broken but has no path that ends in you being fixed.
