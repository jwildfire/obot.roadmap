safety.viz release review 2026-10-03

What v1.9.0 adds, annotated

safety.viz opens its shared parts to a second chart library, and the demo app now carries that library’s four biomarker charts in a tab of their own, with R’s tests one press away. No existing chart, setting or API changes: what is new is the Biomarkers tab, R started on request, the chart list’s format version 2, and the kit those charts are built on.

17 of 17 charts ready on the pilot study R on request: 13.26 MB, once the kit: 36 parts, public from v1.9.0 single file: 1,165,774 bytes, no requests safety.viz dev at 096cc26

What to look at

  1. Open the Biomarkers tab: four charts, each ready, and the app counts 17 of 17 charts on the pilot study.
  2. Choose Alanine Aminotransferase in the group comparison before pressing anything: every visit’s line says statistics need R and what starting it costs, and nothing has been fetched.
  3. Press Start R. It reads Starting R…, then R started, and each visit prints R’s one-way ANOVA across the three arms: at Week 4, p = 0.005 for 75, 67 and 65 participants. Desktop R gives the same.
  4. Open the single-file build with the network off: the same tab draws, there is no Start R, and each line says why statistics are unavailable there.

Patch release v1.9.2: a candidate, not yet released

1. Run the demo app on your own machine

One file, scripts/install-demo.mjs, puts the demo app on your own computer. It downloads safety.viz, builds the demo app and opens it in your browser with the pilot study loaded, served to that computer and to nothing else. In a clone you already have, npm run demo does the same. This is the task for a script that installs and runs the demo app (safety.viz#214), merged by its pull request (safety.viz#215).

$ node install-demo.mjs --ref dev --no-open --port 8711

Try it, on the candidate

curl -fsSLO https://raw.githubusercontent.com/jwildfire/safety.viz/dev/scripts/install-demo.mjs
node install-demo.mjs --ref dev
  1. Check that you have Node.js 22 or later and git: node --version and git --version.
  2. In a folder of your choice, run the two lines above. In Windows PowerShell write curl.exe in place of curl.
  3. Wait for the line “The safety.viz demo app is running at http://127.0.0.1:8642/”. Your browser opens at that address. Here it took under a minute.
  4. Read the tabs: Biomarkers 5 of 5. Click Data: “18 of 18 charts ready”, on the Pilot study.
  5. Press Ctrl+C in the terminal. The demo stops, and the address no longer answers.
  6. Run node install-demo.mjs again, or cd safety.viz and npm run demo. It starts in a few seconds, with nothing downloaded or installed a second time.

Before the release, keep --ref dev

  • Left out, the installer downloads the latest release, v1.9.1, which has no demo command, and stops with “safety.viz 1.9.1, in /…/safety.viz, has no demo command: it came in v1.9.2.”
  • That download of v1.9.1 stays in the safety.viz folder, and an install is never moved to another release. Run it again into another folder: node install-demo.mjs --ref dev --dir safety.viz-dev.
  • Both were run for this page, and the installer said what the two lines above say.

What it does, in order

  1. It checks before it changes anything. Node.js 22 or later, git and npm must be there, and the folder it installs into must be absent, empty or already a safety.viz clone. If not, it says what it found and where to get what is missing, and stops with “Nothing was changed.”
  2. It downloads one release with git, without its history, into ./safety.viz. With no --ref that is the main branch, which holds the latest release.
  3. It installs the tools the release’s lock file names, with npm ci, inside that folder.
  4. It builds the demo app into build/demo inside that folder: the page, the app, the single-file build, every demo study, the typefaces, bio.viz’s bundle and gsm.bio’s statistics file.
  5. It serves that folder at http://127.0.0.1:8642/, or at the next free port if that one is busy, prints the address and opens it in your browser.

What it needs

  • Node.js 22 or later, which brings npm, and git.
  • A network connection, for the download from GitHub and the tools from npm.
  • About 275 MB of disk. Measured on the run above: 127 MB of build tools, 14 MB of built demo, and the rest the release’s own files.
  • That is the cost of building from source. A demo already built and attached to the release would need no build tools and no git, and is not in this release.

What it touches on your machine

  • One folder: safety.viz in the folder you ran it from, or the one you name with --dir. The download, the tools and the built demo are all inside it.
  • npm’s own cache of downloads in your home folder, as any npm install does.
  • One port on 127.0.0.1 while it runs.
  • Your browser, which it opens at the address unless you pass --no-open.
  • Nothing else. It installs nothing outside that folder and changes no setting, so the folder is the whole install.

Who can reach the page

  • The server listens on 127.0.0.1 only, so no other computer can open the page.
  • It refuses a request that names any host but 127.0.0.1 or localhost, so a page on another site cannot read the demo through your browser.
  • It only reads. It gives no file from outside the built demo’s folder, and it accepts nothing sent to it.
  • Files you load are read in your browser. The one thing the page asks the network for is R, from webr.r-wasm.org, and only when you press Start R.

Stopping, starting again, and the options

  • Ctrl+C stops it. Stopping the installer stops the demo with it and frees the port.
  • Run it again to start it again. A clone already in the folder is used as it is.
  • An install is never moved to another release. Give a later release a folder of its own: --ref v1.9.3 --dir safety.viz-1.9.3.
  • --port names the port, --no-open leaves the browser alone, and --help lists every option.
  • If the download is cut off, the installer stops with git’s own message and leaves nothing behind. Run it again. That happened once while this page was made.

What was tried, and what was not

  • macOS with Node 24: the installer was run end to end from an empty folder, for its pull request and again for this page on 2026-10-07. Stopped with an interrupt, it freed the port. Run again, it started without downloading or installing anything.
  • Linux with Node 22: the test runner. The installer’s tests run the file itself against small made-up releases, with nothing installed from the network. A browser test starts the demo command, reads the address it prints, and holds the page to the pilot study with every chart supported, R starting on request and a clean stop.
  • Windows: written for, and not yet tried. There the installer starts npm through a shell, and the demo opens the browser with cmd /c start.
  • A Node older than 22: the file is written so that an old Node can read it and be told it is too old. It has not been run on one.
  • Ten behaviours were broken on purpose, and each failed its test. Among them: the server answering on every network interface, a path climbing out of the folder, and a release named over an existing install.
  • An independent reviewer read the first version and found three faults, each fixed with a test: a named release was ignored once a clone existed, every run installed again, and stopping the installer alone left the demo running.

2. The biomarker charts, rebuilt on bio.viz v0.3.0 and gsm.bio v0.3.0

In the demo app’s Biomarkers tab, the group comparison opens on a trend tile for every biomarker. A tile opens that biomarker across the visits, with R’s test under each visit once R is started. A visit opens alone, and a trail leads back. The cross-tabulation joins as a fifth biomarker chart. This is the requirement that the group comparison opens on trends over time and drills down to one visit (obot.roadmap#367), brought to the app by the task to rebuild it on bio.viz v0.3.0 (safety.viz#212) and its pull request (safety.viz#213).

Try it

Open the demo app on the dev site
  1. Click the Biomarkers tab. It reads 5 of 5: Group comparison, Association scatter, Correlation matrix, Biomarker screen, Cross-tabulation. On the Data view the app counts 18 of 18 charts.
  2. The group comparison opens on 28 trend tiles, a line for each arm and no statistic. The first line says 9 unscheduled visits are not drawn.
  3. Click the Alanine Aminotransferase tile. Ten visits are drawn, Baseline to Week 26, and the One-way ANOVA row reads “Statistics unavailable”.
  4. Press Start R, at the left beneath the tabs. It downloads about 13 MB, once, from webr.r-wasm.org, and the study’s data stays in the browser. The row then reads p = 0.515, 0.127, 0.005, 0.037, 0.013, 0.380, 0.170, 0.050, 0.517, 0.252.
  5. Click Week 4 under the picture. That visit opens alone: the Visit control reads “1 of 10”, and the line reads “One-way analysis of variance: p = 0.005 (Placebo n = 75, Xanomeline High Dose n = 67, Xanomeline Low Dose n = 65)”.
  6. Read the trail above the chart: All biomarkers › Alanine Aminotransferase over time › Week 4. Click a step to go back to it.
  7. Open Cross-tabulation. ARM by EOSSTT counts 58 and 28, 27 and 45, 25 and 71, total 254, and the line reads “Pearson's Chi-squared test: p < 0.001 (n = 254)”.
  8. Under Test, choose Fisher’s exact test. The line reads “Fisher's Exact Test for Count Data: p < 0.001 (n = 254)”.

The detail the release notes leave out

  • The copies: bio.viz’s bundle and gsm.bio’s statistics file are copied from their release tags, bio.viz v0.3.0 and gsm.bio v0.3.0. The test runner holds each copy to its tag, byte for byte.
  • How the three levels work, their settings and what R is asked at each are on the demo page of those two releases: the tiles, one biomarker over time and one visit. This note shows them only as the demo app draws them on the pilot study.
  • Before R: the tiles ask R for nothing. Over time, the test row reads “Statistics unavailable” and the line under the chart says what starting R costs. No request had gone to R’s host before the press.
  • Starting R, measured here: 13.25 MB in 7 requests, all to webr.r-wasm.org, once. Every biomarker chart then uses that one R. Opening the visit, the cross-tabulation and the biomarker screen fetched nothing more from it.
  • The numbers: desktop R, with base R alone on the study’s own files, gives the same ten p-values with the same number in each arm, and the same table and both tests for the cross-tabulation. The script and its answers are beside this page.
  • The ten p-values are also the ones in the table in section 02 below. The test and the data have not changed, only where the chart prints them.
  • Who is counted: the subject-level file has 254 participants. The labs file also carries 110 synthetic participants who are in no other file, and the biomarker charts leave them out and say so.
  • The single-file build, opened with the network off, draws every chart and each level of the group comparison and sends no request. A browser test holds it to that.
  • What did not move: no safety chart’s source, bundle, demo page or data is in the change. The app’s count goes from 17 charts to 18, and from four biomarker charts to five.
  • Tests: 2,239 unit tests and 385 browser tests pass. One browser test walks this tab with real R started in the browser and holds each of R’s answers to desktop R’s on the same rows.

Not in the release

  • The group comparison’s difference grid, a second opening view, is paused and has a requirement of its own (obot.roadmap#371). bio.viz v0.3.0 does not ship it, so the app does not draw it and asks R for nothing for it.

Known, and not fixed

  • On the Biomarker screen, under Compare, the chart prints a sentence telling the reader to give an outcomes table by calling init(). A reader of the app cannot do that. It has been bio.viz’s wording since v0.2.0, and rewording it is in the backlog (bio.viz#119).
  • On a phone, the row labels of the table over time break inside a word, as the second phone picture above shows. It was seen while this page was captured and has no issue yet.
  • The installer has not been tried on Windows, as said above.

Where to look further

  • The release notes, as they will publish.
  • The README’s section on running the demo app on your own machine, and the installer itself, one file to read before you run it.
  • The demo of bio.viz v0.3.0 and gsm.bio v0.3.0, for the three levels in full.

Patch release v1.9.1

A patch on everything below. Nothing is removed, and no chart’s drawing changes except the histogram’s, which now draws its two deprecation notes.

  • The demo app’s footer says what happens to the data you load: files are read in the browser and never uploaded, and starting R downloads R from webr.r-wasm.org while your data stays in the browser. The single file says it loads nothing (safety.viz#196).
  • The histogram’s two JavaScript p-values, the normality screen and the group comparison, are deprecated. They still work, and the chart says so. v1.10.0 removes them, so remove test_normality and compare_distributions from your settings; nothing in safety.viz replaces them (safety.viz#188).
  • A library chart named data is refused, because the app keeps that name for its data view (safety.viz#197).
  • Each requirement ID now names one requirement, and every evidence page shows its own requirement text (safety.viz#195).
  • Evidence screenshots can be refreshed by name, and the obot app can start that refresh itself (safety.viz#204, safety.viz#207).

02 · R on request

R on request

One press starts R in your browser, once, from webR’s public host with gsm.bio’s statistics functions, and every biomarker chart uses that one R from then on.

The single file, offline

The single-file build carries bio.viz’s charts inline and still loads nothing, so it cannot start R. It has no Start R control, and its biomarker charts say why statistics are unavailable.

03 · a second library joins

A second library joins the app

A page that mounts the demo app can hand it another chart library: its chart factories and its own chart list. The app lists those charts in a tab of their own, gives each a status, counts them, builds their settings and data from the loaded files and the mapping, and draws one at a time, as it does its own. To describe charts like these, the chart list’s format goes to version 2: an entry can name its library, the group it is listed under, and the named tables its chart takes. The thirteen safety charts’ entries mean what they meant.

Why it matters

Before this, the app knew only its own charts. Now any library that publishes a chart list in this format can join it, on the same files and mapping, without the app being rebuilt around it.

Try it

Open the Domains page
  1. Find “Biomarkers, from bio.viz” near the end.
  2. Follow a chart’s API reference link to bio.viz’s site.
04 · the kit

The kit

SafetyViz.kit hands out the parts every safety.viz chart is built from, so a library loaded beside it builds charts that look and behave the same, without a copy of that code drifting away: the control sidebar and its builders, the filter contract, the axis-limit helpers, the record listing, the participant rail, the box drawing, the measure list, the Kaplan–Meier estimator and the Chart.js the bundle already contains. Each member is the very function the charts call. bio.viz’s four charts are built on it.

The one commitment in this release

From v1.9.0 the kit is public surface: a change to any member’s name, signature, return value, or the elements and class names it produces is a breaking change. Adding a member is not. The kit, explained in one page, and its API reference.

before you approve

What is not in this release

  • R in the single file: it loads nothing, so its biomarker charts say statistics are unavailable.
  • A library other than bio.viz in the app: the seam is general, and bio.viz is the only one using it.
